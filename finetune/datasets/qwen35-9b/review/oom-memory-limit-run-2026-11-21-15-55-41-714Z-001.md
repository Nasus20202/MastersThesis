## Final report

## Summary

The application has been successfully restored to a stable, healthy state.

**Root Cause Identified:**

- The nginx container had memory limits set to only **4Mi**, which is insufficient for the nginx:1.31.5 image
- This caused both pods to be `OOMKilled` repeatedly, resulting in CrashLoopBackOff states
- Exit code 128 with message "container init was OOM-killed (memory limit too low?)"

**Fix Applied:**
Updated the deployment's resource requirements:

```bash
kubectl set resources deployment/app -n default --limits=memory=128Mi --requests=memory=64Mi
```

**Verified Outcomes:**

- ✅ Both pods show `READY 1/1` and `STATUS Running`
- ✅ Zero restarts (was 2+ before, now 0)
- ✅ Deployment has `2/2 READY`, `2/2 UP-TO-DATE`, `2/2 AVAILABLE`, `0 unavailable`
- ✅ Deployment condition `Available: True` with `MinimumReplicasAvailable`
- ✅ Memory limits are correctly set to `128Mi` and requests to `64Mi`

The application is now running stably without repeated restarts.
