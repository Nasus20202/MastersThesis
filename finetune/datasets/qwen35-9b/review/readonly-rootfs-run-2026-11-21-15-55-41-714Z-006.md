## Summary

**Root Cause**: The nginx container had `readOnlyRootFilesystem: true` set, which prevented nginx from writing necessary runtime files during startup:

- `/etc/nginx/conf.d/default.conf` (config modification - informational warning)
- `/var/cache/nginx/client_temp` (temp file directory - caused failure)
- `/run/nginx.pid` (PID file - caused failure)

**Fix Applied**: Updated the deployment to add emptyDir volume mounts providing writable space for nginx's runtime needs:

- `/tmp` → tmp-empty (for temp files)
- `/var/cache/nginx` → cache-empty (for nginx cache)
- `/var/run` → pid-empty (for PID file)

The root filesystem remains read-only; only these specific mounted volumes provide write access.
