## Task

A Kubernetes application is restarting repeatedly and never stays healthy. Restore it to a stable, Ready state.

Documented in:

- content/en/docs/tasks/configure-pod-container/assign-memory-resource.md: Specify a memory request and a memory limit, Exceed a Container's memory limit

## Write commands

1. `kubectl patch deployment app -n default --type=strategic -p='{"spec":{"template":{"spec":{"containers":[{"name":"app","resources":{"limits":{"memory":"128Mi"},"requests":{"memory":"64Mi"}}}]}}}}'`

## Final report

## Summary

**Root Cause**: The nginx container was configured with an insufficient memory limit of only **4Mi**, which caused the container's init process to be OOM-killed immediately on startup. This led to repeated CrashLoopBackOff restarts.

**Fix Applied**: Updated the deployment `app` in namespace `default` with proper memory resources:

- Increased `limits.memory` from 4Mi to **128Mi**
- Added `requests.memory` of **64Mi** (was not previously set)

**Verification - Before Fix**:

- Pods: `0/1 Ready`, Status: `CrashLoopBackOff`, Restarts: 7 each
- Deployment: `READY 0/2`, `AVAILABLE 0/2`

**Verification - After Fix**:

- Pods: `1/1 Ready`, Status: `Running`, Restarts: 0 each
- Deployment: `READY 2/2`, `UP-TO-DATE 2`, `AVAILABLE 2/2`

The application is now stable and all replicas are in a healthy, ready state.
