## Final report

Stable. All warning events are historical (the last ones are 3m21s+ old, from pod startup and the old ReplicaSet) — no new failures since the fix.

## Summary

**Root cause:** The `app` Deployment's pod template limited `memory` to **4Mi** — far below what the pod needs just to initialize. The kubelet therefore killed the container during init every time:

```
failed to create containerd task: ... container init was OOM-killed (memory limit too low?)
```

Because the container died before nginx could bind port 80, the readiness probe (`tcpSocket :http`, `failureThreshold: 1`) always reported `connect: connection refused`, so pods cycled through `OOMKilled` → `CrashLoopBackOff` and never became Ready. Comparing ReplicaSet history confirmed the regression: revision 1 (`app-6b5786fd`) used `limits.memory: 64Mi`, revision 2 (`app-774f56f755`) reduced it to `4Mi`.

**Change made** — one targeted patch to the persistent owner (the Deployment), restoring the last known-good limit:

```
kubectl patch deployment app -n default --type=strategic \
  -p '{"spec":{"template":{"spec":{"containers":[{"name":"app","resources":{"limits":{"memory":"64Mi"}}}]}}}}'
```

Nothing else was touched — image (`nginx:1.31.5`), replicas (2), probes, ports, and `Recreate` strategy are unchanged. Old pods were not deleted manually; they were replaced by the Deployment's own rollout.
