# image-pull-failure · deepseek-flash · run-2026-11-21-11-26-46-021Z · attempt 4

## Task

An application in the Kubernetes cluster is unhealthy. Restore it to a healthy state.

Documented in:

- content/en/docs/concepts/containers/images.md: Updating images > ImagePullBackOff

## Write commands

1. `kubectl -n default patch deploy app --type=json -p='[{"op":"replace","path":"/spec/template/spec/containers/0/image","value":"nginx:1.31.5"}]'`

## Final report

The application is restored to a healthy state.

## Root cause

The `default/app` Deployment (generation 2) had a typo in its container image: `ngnix:1.31.5` instead of `nginx:1.31.5`. The new ReplicaSet `app-5866bbf94f` therefore could not pull its image, leaving a pod stuck in `ImagePullBackOff` and the Deployment reported as `replicas: 4, unavailableReplicas: 1, updatedReplicas: 1` (surge pod from the failed rolling update).

Evidence from the kubelet events:

```
Failed to pull image "ngnix:1.31.5": ... docker.io/library/ngnix:1.31.5: not found
Error: ErrImagePull → BackOff / ImagePullBackOff
```

## Fix

Single-field patch on the owning Deployment — corrected only the image reference (the previously working ReplicaSet `app-6494bb7f99` already ran `nginx:1.31.5`):

```
kubectl -n default patch deploy app --type=json \
  -p='[{"op":"replace","path":"/spec/template/spec/containers/0/image","value":"nginx:1.31.5"}]'
```

No other spec fields (replicas=3, selector, strategy, ports) were changed.
