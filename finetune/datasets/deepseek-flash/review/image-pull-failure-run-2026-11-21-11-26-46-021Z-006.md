# image-pull-failure · deepseek-flash · run-2026-11-21-11-26-46-021Z · attempt 6

## Task

An application in the Kubernetes cluster is unhealthy. Restore it to a healthy state.

- content/en/docs/concepts/containers/images.md: Updating images > ImagePullBackOff

1. `kubectl set image deploy/app app=nginx:1.31.5 -n default --record=false`

## Final report

The application is healthy again.

## Root cause

The `app` Deployment in namespace `default` had been rolled to a new pod template (revision 2) with a misspelled image tag:

- **Bad (revision 2):** `ngnix:1.31.5` → `docker.io/library/ngnix:1.31.5: not found`
- **Working (revision 1, still serving):** `nginx:1.31.5`

Because the image never resolved, the new ReplicaSet `app-5866bbf94f` stayed at 0/1 ready, its pod `app-5866bbf94f-872s2` sat in `ImagePullBackOff`, `progressDeadlineSeconds: 600` was ticking toward a failed rollout, and the Deployment showed `unavailableReplicas: 1` with `replicas: 4` (3 old + 1 bad surge pod).

## Fix (single, minimal change)

Corrected the container image reference on the owning resource:

```
kubectl set image deploy/app app=nginx:1.31.5 -n default
```

No other fields, replicas, strategy, or limits were touched. The transient bad pod was not manually deleted — it was removed naturally by the ReplicaSet scaling down to 0.
