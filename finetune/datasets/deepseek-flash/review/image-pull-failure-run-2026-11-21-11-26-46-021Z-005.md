# image-pull-failure · deepseek-flash · run-2026-11-21-11-26-46-021Z · attempt 5

## Final report

The application is restored to health.

## Root cause

Deployment `default/app` (3 replicas) had its container image changed to a misspelled reference, `ngnix:1.31.5`. The registry has no such repository, so the new ReplicaSet `app-5866bbf94f` could never start its pod:

- Pod `app-5866bbf94f-flkxz` stuck in `ImagePullBackOff` (0/1 ready)
- Kubelet event: `Failed to pull image "ngnix:1.31.5": ... docker.io/library/ngnix:1.31.5: not found`
- Deployment showed `updatedReplicas=1`, `unavailableReplicas=1`, with the `Progressing` condition stuck on `ReplicaSetUpdated`

Rollout history confirmed the drift was introduced in revision 2 — revision 1 had used the valid `nginx:1.31.5`, matching the three still-healthy pods from ReplicaSet `app-6494bb7f99`.

## Change made

A single-field fix to the owning resource, leaving every other setting untouched:

```
kubectl set image deploy/app -n default app=nginx:1.31.5
```
