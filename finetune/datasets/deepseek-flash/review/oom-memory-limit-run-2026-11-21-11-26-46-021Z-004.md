# oom-memory-limit · deepseek-flash · run-2026-11-21-11-26-46-021Z · attempt 4

## Task

A Kubernetes application is restarting repeatedly and never stays healthy. Restore it to a stable, Ready state.

Documented in:

- content/en/docs/tasks/configure-pod-container/assign-memory-resource.md: Specify a memory request and a memory limit, Exceed a Container's memory limit

## Final report

## Root cause

The `app` Deployment (namespace `default`, image `nginx:1.31.5`) had its container memory limit set to **4Mi**. That is below what the nginx image needs just to exec, so the container was killed during init, never reaching a serving state:

```
Reason: StartError
Message: failed to create containerd task: ... container init was OOM-killed (memory limit too low?)
Exit Code: 128   →  Repeat restarts → CrashLoopBackOff
```

Readiness probe failures (`dial tcp :80: connection refused`) were a symptom of the container dying, not a separate fault — and there was no Service or LimitRange/ResourceQuota involved.

## Change made (single, minimal)

Patched only the container's memory resources on the Deployment that owns the faulty pods:

```yaml
resources:
  requests: { memory: 32Mi } # was unset (defaulted to 4Mi)
  limits: { memory: 64Mi } # was 4Mi
```

Left untouched: replica count (2), image `nginx:1.31.5`, container port, readiness probe, `Recreate` strategy, labels/selector.

## Verified outcome (fresh observations)

- **Controller replicas match:** `app  2/2 READY  UP-TO-DATE 2  AVAILABLE 2`; `rollout status` reported `deployment "app" successfully rolled out`; new ReplicaSet `app-6d6fc99cbd` has DESIRED 2 / CURRENT 2 / READY 2.
- **Pods stable & Ready:** `app-6d6fc99cbd-rwzjk` and `-vqr7z` both `1/1 Running`, `ready=True`, **restarts=0**, no terminated lastState — re-checked at 24s, 94s and 135s of age.
- **Traffic actually served (not just object health):** in-pod request to port 80 returned `HTTP/1.1 200 OK`.
- **Limit is adequate, not excessive:** cgroup `memory.current` ≈ 15.2 MB / 15.6 MB vs the 64Mi limit (~24% used).
- **No recurrence:** no `OOM-killed` or `BackOff` events for the new ReplicaSet after the change (only Normal events: Scheduled/Started).
