## Final report

**Root cause:** Deployment revision 2 added `securityContext.readOnlyRootFilesystem: true` but nginx needs writable paths. The container crashed with:

```
nginx: [emerg] mkdir() "/var/cache/nginx/client_temp" failed (30: Read-only file system)
```

so the new ReplicaSet (`app-5fdc8854df`) never became ready and the rollout stalled (`updatedReplicas=1`, `unavailableReplicas=1`) behind the old healthy ReplicaSet.

**Change (smallest justified):** kept `readOnlyRootFilesystem: true` and mounted `emptyDir` volumes over only the ephemeral paths nginx writes:

```yaml
volumeMounts:
- mountPath: /var/cache/nginx  (emptyDir: nginx-cache)
- mountPath: /var/run          (emptyDir: nginx-run)
```
