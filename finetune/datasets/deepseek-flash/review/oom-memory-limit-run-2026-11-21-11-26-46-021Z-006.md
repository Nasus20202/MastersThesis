# oom-memory-limit · deepseek-flash · run-2026-11-21-11-26-46-021Z · attempt 6

## Task

A Kubernetes application is restarting repeatedly and never stays healthy. Restore it to a stable, Ready state.

Documented in:

- content/en/docs/tasks/configure-pod-container/assign-memory-resource.md: Specify a memory request and a memory limit, Exceed a Container's memory limit

## Write commands

1. `kubectl patch deploy app --type=strategic -p '{"spec":{"template":{"spec":{"containers":[{"name":"app","resources":{"limits":{"memory":"64Mi"}}}]}}}}'`
2. `kubectl run curl-check --rm -i --restart=Never --image=curlimages/curl:8.10.1 --command -- sh -c 'for ip in $(getent hosts $HOSTS 2>/dev/null)`
3. `kubectl run curl-check --rm -i --restart=Never --image=curlimages/curl:8.10.1 --command -- sh -c 'curl -sS -o /dev/null -w "pod 10.244.0.9 -> HTTP %{http_code}\n" --max-time 5 http://10.244.0.9/`

## Final report

## Root cause

`deployment/app` in the `default` namespace set `resources.limits.memory: 4Mi` on the nginx container. That limit is smaller than what nginx's own init requires, so the container was killed before it could ever start. The evidence was not a generic crash but a runtime-level OOM at container init:

```
Last State: Terminated
  Reason:  StartError
  Message: failed to create containerd task: ... runc create failed:
           unable to start container process: container init was OOM-killed (memory limit too low?)
Events: Warning Failed ... container init was OOM-killed (memory limit too low?)
Events: Warning BackOff ... Back-off restarting failed container app
```

Because the init was killed, the `tcpSocket: 80` readiness probe also failed (`connection refused`), and the Deployment reported `MinimumReplicasUnavailable`. I checked for `LimitRange`/`ResourceQuota` in `default` first — none existed, so the pod's `requests: 4Mi` was just Kubernetes defaulting requests from the limit, and no admission policy constrained how high I could raise it.

There is no Service fronting this app (only the built-in `kubernetes` Service exists), so verification was done directly against pod IPs.

## Change made

One field only, on the owning Deployment, via strategic merge patch:

```
spec.template.spec.containers[app].resources.limits.memory: 4Mi -> 64Mi
```

Everything else was left intact: `replicas: 2`, `image: nginx:1.31.5`, `strategy: Recreate`, the readiness probe, ports, and pull policy (confirmed in the post-change spec dump).
