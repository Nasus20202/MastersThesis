# bind-precreated-pv · deepseek-flash · run-2026-11-21-11-26-46-021Z · attempt 1

## Task

The cluster has a pre-created PersistentVolume named app-pv with storageClassName manual and 1Gi capacity. Create a PersistentVolumeClaim named app-pvc that binds to it and a Pod named app (image nginx:1.31.5) that mounts the claim at /data.

Documented in:

- content/en/docs/concepts/storage/persistent-volumes.md: Introduction, Claims As Volumes > PersistentVolumes typed `hostPath`

4. `kubectl apply -f /tmp/work/app-pod.yaml`

## Final report

Done. Both objects are created in `default` and verified.

**What I created (smallest change, no pre-existing resources modified):**

```yaml
# PersistentVolumeClaim app-pvc
spec:
  storageClassName: manual
  volumeName: app-pv # pins the bind to the pre-created PV
  accessModes: [ReadWriteOnce]
  resources.requests.storage: 1Gi
```

```yaml
# Pod app
image: nginx:1.31.5
volumeMounts: [{ name: data, mountPath: /data }]
volumes: [{ name: data, persistentVolumeClaim: { claimName: app-pvc } }]
```

I matched the PVC's request to the PV's `1Gi`/`RWO`/`manual` attributes (mismatched class or size is the usual reason such a claim stays `Pending`) and set `volumeName` so it binds to `app-pv` rather than any other candidate.
