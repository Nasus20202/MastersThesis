# readonly-rootfs · deepseek-flash · run-2026-11-21-11-26-46-021Z · attempt 6

## Task

The application rollout stopped completing after its container root filesystem was made read-only. Restore the application while keeping the root filesystem read-only.

Documented in:

- content/en/docs/tasks/configure-pod-container/security-context.md: Set the security context for a Container

## Write commands

1. `kubectl -n default patch deployment app --type=strategic --patch-file /tmp/patch.yaml`

## Final report

Everything checks out. Summary of what I found and did:

## Root cause

The Deployment `app` (nginx:1.31.5) had `securityContext.readOnlyRootFilesystem: true`, but nginx requires writable scratch paths at startup. The new ReplicaSet `app-5fdc8854df` pods crash-looped with:

```
nginx: [emerg] mkdir() "/var/cache/nginx/client_temp" failed (30: Read-only file system)
```

```
Warning BackOff ... Back-off restarting failed container app
```

Old pods kept serving, so the Deployment showed `3/3` but the rollout was stuck at `updatedReplicas: 1`, `unavailableReplicas: 1` with a failing `Progressing` condition.

## Fix (smallest change, constraint preserved)

Patched the Deployment's pod template to mount `emptyDir` volumes over only the paths nginx must write, keeping the root filesystem read-only:

- volume `nginx-cache` → mountPath `/var/cache/nginx`
- volume `nginx-run` → mountPath `/var/run` (nginx pid file)

`readOnlyRootFilesystem: true` and the image `nginx:1.31.5` were left untouched.

## Verified outcome

- Rollout: `deployment "app" successfully rolled out`; status now `readyReplicas: 3`, `updatedReplicas: 3`, `availableReplicas: 3` (spec replicas = 3, all match), condition `Progressing=NewReplicaSetAvailable`, old ReplicaSets scaled to 0.
- Pods: 3 × `app-795b9c574c-*` all `1/1 READY`, `RESTARTS 0`, no errors in logs, readiness (tcpSocket :80) passing.
- Constraint still enforced inside every pod: `touch /rootfs-test` → `Read-only file system` (rc=1), while `/var/cache/nginx` is writable and contains `client_temp proxy_temp fastcgi_temp scgi_temp uwsgi_temp`.
- Functional check: HTTP requests return `http_code=200` on `127.0.0.1` and on all three pod IPs (`10.244.0.9`, `10.244.0.10`, `10.244.0.11`). No `app` Service exists in the namespace, so requests were verified directly against pod endpoints.
