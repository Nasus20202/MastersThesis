# oom-memory-limit · deepseek-flash · run-2026-11-21-11-26-46-021Z · attempt 5

## Task

A Kubernetes application is restarting repeatedly and never stays healthy. Restore it to a stable, Ready state.

Documented in:

## Final report

## Root cause

The `app` Deployment in `default` had its container memory limit set to **`4Mi`**, which is below what the nginx entrypoint needs even to finish container init. The kubelet/containerd reported:

```
runc create failed: unable to start container process:
container init was OOM-killed (memory limit too low?)   (Exit Code 128, Reason: StartError)
```

The container never got past init, so each attempt was counted as a crash → `CrashLoopBackOff` on both replicas, `Available=False (MinimumReplicasUnavailable)`, `unavailableReplicas: 2`.

Evidence that `4Mi` was a regression rather than intent: the superseded ReplicaSet `app-6b5786fd` (Deployment revision 1, still in history) declared `memory: 64Mi` for the identical container spec — image, port, and probes were unchanged; only `resources.limits.memory` had been lowered from `64Mi` to `4Mi`.

## Change made

One field, on the owning persistent resource (the Deployment), nothing else touched:

```
kubectl -n default patch deploy app --type=strategic \
  -p '{"spec":{"template":{"spec":{"containers":[{"name":"app","resources":{"limits":{"memory":"64Mi"}}}]}}}}'
```

No changes to replicas (2), image (`nginx:1.31.5`), probes, ports, or strategy; no pods deleted by hand — the Deployment's own rolling replacement handled it.
