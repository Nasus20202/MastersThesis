## Final report

The application has been successfully restored while preserving the read-only root filesystem constraint.

**Root Cause:**
The container's root filesystem was set to read-only (`readOnlyRootFilesystem: true`), but the Nginx application requires writing to certain directories during startup and operation. The container was crashing with:
`nginx: [emerg] mkdir() "/var/cache/nginx/client_temp" failed (30: Read-only file system)`

**Resolution:**
I added an `emptyDir` volume named `writable-data` to the `app` Deployment and mounted it to the directories Nginx needs write access to:
- `/var/cache/nginx` (for temporary cache files)
- `/tmp` (for general temporary files)
- `/var/run` (for PID files)
